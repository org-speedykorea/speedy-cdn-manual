SSL 인증서 & HTTPS 설정 가이드

도메인 SSL 인증서 self-upload(신규·수정·최종 배포·취소·조회·삭제)와 HTTPS·HTTP2 설정, 도메인 정보 조회를 API로 관리합니다.

개요 & 제공 기능

본 API는 도메인에 대한 SSL 인증서와 HTTPS / HTTP2 설정을 관리하는 기능을 제공합니다. 고객이 직접 발급·보유한 인증서를 업로드(self-upload)하여 Speedy CDN 도메인에 적용할 수 있습니다.

지원 프로토콜 — 모든 데이터는 SSL(HTTPS) 기반 REST(HTTP POST/GET) 로 송·수신합니다. 요청은 API에 따라 multipart/form-data, application/json, URL Query Parameter(GET) 형식을 사용하며, 응답은 application/json 입니다.

BASE URL  ·  https://openapi.cloudn.co.kr/cdnservice/{Method Name}

인증 방식

모든 요청은 User Portal 계정으로 인증합니다. 계정 ID(id)와 함께 비밀번호(password) 또는 API KEY(cloud_key_value) 중 택1을 보냅니다. form-data 방식은 폼 필드로, JSON 방식은 api_request.common 아래에, GET 방식은 쿼리 파라미터로 넣습니다.

배포 순서 & 검증 가이드

인증서 배포와 도메인 HTTPS·HTTP2 설정은 공통으로 사전 배포(Staging) → 검증 → 최종 배포 절차를 따릅니다.

1

사전 배포 요청

SSL 인증서 또는 도메인 HTTPS·HTTP2 설정 변경을 Staging에 등록

2

Staging 서버 반영

실서비스에는 반영되지 않고 Staging 서버에만 적용

3

Staging 검증

Staging 서버 IP로 직접 요청 + Host Header에 도메인 지정

✓

최종 배포

검증 통과 시 최종 배포 요청 → 운영 서버 반영 완료

  • 사전 배포가 성공적으로 등록되어야 최종 배포가 가능합니다.
  • 사전 배포가 실패하면 사전 배포 취소 후 재 사전 배포를 진행하고, 검증 완료 후 최종 배포합니다.
  • 사전 배포 완료 후에는 Staging 서버 IP로 직접 요청하고 도메인 Host Header를 지정하여 정상 동작을 확인합니다. Staging 서버 IP는 배포 이력 조회 응답의 pv_ip 로 확인합니다.
⚠️ 최초 적용 시 필수 순서: 인증서 배포 후 도메인 HTTPS ON — 도메인에 인증서를 처음 연결할 때는 아래 순서를 반드시 지킵니다.
SSL 인증서 배포 완료(최종 배포까지)→ 도메인 HTTPS ON 사전 배포→ Staging 검증→ 도메인 HTTPS ON 최종 배포→ 연결 완료
최초 1회 연결 이후(이미 도메인 HTTPS ON 이 적용된 도메인)에는 도메인 설정이 인증서를 참조하고 있으므로 인증서 배포(사전/최종)만으로 갱신됩니다.
실패 시 재시도 경로   사전 배포 취소→재 사전 배포→재검증→최종 배포 요청

시나리오별 순서

실무에서 자주 사용하는 4가지 배포 시나리오입니다.

시나리오순서
1. 신규 등록
정상
SSL 신규 사전 배포→SSL 최종 배포→도메인 HTTPS·HTTP2 사전 배포→Staging 검증→도메인 HTTPS·HTTP2 최종 배포
2. 수정 (도메인 추가)
정상
SSL 수정 사전 배포(도메인 추가)→SSL 최종 배포→도메인 HTTPS·HTTP2 사전 배포→Staging 검증→도메인 HTTPS·HTTP2 최종 배포
3. 수정 (인증서 갱신)
정상
SSL 수정 사전 배포(인증서 갱신)→Staging 검증→SSL 최종 배포

이미 도메인 HTTPS ON 이 적용된 도메인 기준입니다. 사전 배포 시 갱신 인증서가 도메인 Staging 에 반영되며, 검증 후 SSL 최종 배포로 운영 반영이 완료됩니다.

4. 사전 배포 실패
실패
사전 배포→실패 확인→Staging 취소→재 사전 배포→재검증→대상 설정 최종 배포

Staging 실패 시에는 취소 후 재배포가 필수이며, 재검증 완료 후 최종 배포를 진행합니다.

SSL 인증서 신규 등록 사전 배포 (Staging)

🔷 form-data
https://openapi.cloudn.co.kr/cdnservice/ssl/staging/deploy

신규 인증서를 시스템 DB에 등록하고, domain_list 로 지정한 도메인을 대상으로 Staging 배포를 수행합니다. 사전 배포 및 정상 동작 확인 후 최종 배포할 수 있습니다.

API 호출→SSL 인증서 DB 등록→domain_list 입력 시 도메인 Staging 배포→사전 배포 완료
권장 경로 — domain_list 를 입력하면 사전 배포까지 한 번에 완료됩니다.
예외 경로 — domain_list 없이 등록하면 인증서는 DB에 '등록 완료' 상태로만 저장되고 사전 배포는 수행되지 않습니다. 이후 사전 배포가 필요하면 SSL 인증서 수정 사전 배포를 호출하세요.
등록·배포 조건 (모두 만족해야 함)
  • 유효한 인증서 — 서명 검증에 성공한 형식상 유효한 X.509 인증서. Nginx 에 적용 가능한 형식이어야 하며, 일반적으로 Apache 용으로 발급된 인증서도 등록 가능합니다.
  • 도메인 일치 — 인증서 Common Name(CN)이 domain_list 의 도메인과 일치해야 합니다. CNAME 기준으로 확인하며, CNAME 이 없으면 서비스 URL 기준으로 확인합니다. 와일드카드(*)는 한 단계 하위 도메인만 허용됩니다.
  • 만료되지 않은 인증서 — 유효 기간(NotAfter)이 현재 시각 이후여야 합니다.
  • 암호화된 개인키 — .key 파일이 암호화되어 있으면 ssl_key_password 를 함께 입력해야 합니다.
  • 파일 형식 — 인증서는 .crt 또는 .pem(공개키), 키는 .key 또는 .pem(개인키). 인증서와 개인키는 반드시 분리된 파일이어야 하며, 하나의 .pem 에 함께 들어 있는 형태는 지원하지 않습니다.

실전 예제 — Let's Encrypt 인증서 self-upload

도메인 ic.speedykorea.com(download 서비스)에 Let's Encrypt 인증서를 발급해 self-upload하고 HTTPS를 최초로 켠 전체 과정입니다.

1

LE 인증서 발급

certbot DNS-01
CN=ic.speedykorea.com

2

SSL 사전배포

ssl/staging/deploy
+ domain_list

3

SSL 최종배포

ssl/update

4

HTTPS ON 사전배포

domain/staging/
https/settings

5

Staging 검증

Host헤더+Staging IP
verify=0(OK)

6

HTTPS ON 최종배포

https_enabled: true

① 인증서 발급 (certbot DNS-01)

TXT 레코드 _acme-challenge.ic.speedykorea.com에 검증값을 등록하면 발급됩니다. 발급물 fullchain.pem→.crt, privkey.pem→.key로 분리해 업로드합니다(RSA 2048 권장).

결과 확인

domains/info의 https_enabled가 true로 전환되고, 운영 엣지 TLS 핸드셰이크에서 인증서 체인 검증이 통과(Verify return code: 0)하면 완료입니다.

✅ 검증 완료 — 운영 엣지 전 노드 정상 인증서 서빙, 체인 검증 OK, HTTPS 종단 정상.
① 발급
# DNS-01, RSA 2048
certbot certonly --manual \
  --preferred-challenges dns \
  -d ic.speedykorea.com \
  --key-type rsa --rsa-key-size 2048
②~⑥ 배포 & 검증
# ② SSL 사전배포
POST /ssl/staging/deploy       -> 200
# ③ SSL 최종배포
POST /ssl/update               -> 200
# ④ HTTPS ON 사전배포
POST /domain/staging/https/settings
     https=on http2=on         -> 200
# ⑤ Staging 검증 (TLS 1.2)
openssl s_client -connect <IP>:443 \
  -servername ic.speedykorea.com -tls1_2
  # CN=ic.speedykorea.com / verify=0
# ⑥ HTTPS ON 최종배포
POST /domain/https/settings    -> 200
⚠️ TLS 버전 — CDN 엣지는 TLS 1.2까지 지원(1.3 미지원). 구형 클라이언트(예: macOS 기본 LibreSSL)가 1.3 우선 협상 시 alert이 날 수 있으므로 TLS 1.2로 검증하세요.

result_code의미대응

401인증 정보 오류 (invalid auth info)id / password(또는 API KEY) 확인
403도메인 접근 권한 없음도메인이 속한 계정으로 인증
E500SSL mapping not found 등인증서→도메인 매핑(domain_list) 반영 후 재시도
  • 매핑 반영 지연 — 최종 배포 직후 인증서→도메인 매핑 반영에 수 초가 걸릴 수 있습니다. HTTPS ON 사전배포가 "SSL mapping not found"로 실패하면 잠시 후 재시도하세요.
  • 최초 vs 갱신 — 최초 1회는 HTTPS ON(사전→검증→최종)까지 완료해야 도메인과 인증서가 연결됩니다. 이후 갱신은 인증서 배포만으로 반영됩니다.
  • 인증서 만료 관리 — Let's Encrypt는 90일 유효. 만료 전 재발급 → ssl/staging/update(갱신) → ssl/update로 교체합니다.
